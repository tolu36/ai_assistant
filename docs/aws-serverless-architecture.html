Personal AI Assistant - AWS Serverless Architecture

This deployment runs the app without an EC2 server. Lambda hosts the FastAPI API and static UI, DynamoDB stores dynamic user state, SSM Parameter Store holds hosted secrets, and EventBridge Scheduler triggers the daily 9 AM morning brief email.

Runtime Architecture

Browser UI

  • app/static/index.html
  • app/static/app.js
  • No app-level auth in the single-user MVP

Lambda Function URL

  • Public HTTPS endpoint
  • No API Gateway layer
  • Routes HTTP requests to Lambda

FastAPI in Lambda

  • app/aws_lambda.py
  • Mangum adapts AWS events
  • app/main.py is unchanged app core

DynamoDB

  • Preferences
  • Brief history
  • Schedule proposals
  • Feedback constraints

SSM Parameters

  • SMTP password
  • Mistral API key

Scheduled Email Flow

1. EventBridge Scheduler

Runs at 9:00 AM America/Toronto.

2. Lambda Scheduled Event

app/aws_lambda.py detects aws.scheduler.

3. Brief Generation

RSS feeds are fetched and summarized by brief_generator.py.

4. Email Delivery

The brief is saved to DynamoDB and sent through Gmail SMTP.

Build And Deployment Flow

Tool/File Role Why It Exists
AWS SAM CLI Builds and deploys Lambda/DynamoDB/EventBridge resources. Turns deploy/aws/template.yaml into AWS infrastructure.
deploy/aws/template.yaml Infrastructure definition. Creates Lambda, Function URL, DynamoDB, scheduler, and IAM roles.
Makefile Custom SAM build step. Packages only lightweight Lambda dependencies and avoids Torch/Transformers.
requirements-aws.txt Lambda dependency list. Keeps the Lambda deployment small and fast to cold start.
app/aws_lambda.py Lambda handler. Handles both HTTP requests and scheduled email events.

Storage Modes

Local development uses STORAGE_PROVIDER=sqlite. AWS deployment uses STORAGE_PROVIDER=dynamodb. The route and service APIs stay the same, so the app can run in either mode.

SQLite remains best for local dev. DynamoDB is used in Lambda because Lambda file storage is temporary and not a durable app database.
